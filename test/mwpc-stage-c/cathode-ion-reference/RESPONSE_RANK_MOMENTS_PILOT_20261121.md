# Read-only response-rank and physical-moment pilot (2026-11-21)

**Status: code committed; WSL smoke test and real-data results pending.** This
is a first numerical **gate**, not a claim that nine avalanche descriptors
suffice for NA60+ U/V readout.

## Inputs / provenance

Uses the existing **256-site 10 ns, 100 us** single-positive-ion RKF
`training_bank` in
`templates256_dt10_training.root`, generated by
`rebuild_plane_templates_fine.cc` on the frozen original sites.
That ROOT includes per-site `(u_cm,v_cm,w_cm,original_primary)`,
`waveform_plus_then_minus` (fC/ns), and `average_plus/minus`
histograms that define the exact time grid. This is the **symmetric
nine-wire 2100 V no-field-wire reference**, with two complete analytic
cathode planes, provisional Ar+ mobility in pure Ar. **It is not** an
as-built P3 geometry, U/V stereo strip weighting solution, electron
signal, VMM shaping, or detector performance prediction.

No Geant4, TrackHeed, AvalancheMicroscopic, ion RKF, FEM, or 1000-muon
campaign is executed by this script. It reads ONE existing ROOT file
without opening any file in write mode. Its output is under a NEW
directory that must not already exist.

## Scientific question and strict limitations

The single-ion linear response operator \(H\) maps ion birth position to
the **time-dependent ion-only whole-plane current**. We discretize its
domain at the 256 preselected real microscopic ion-birth positions.
The reported operator rank is conditioned on those particular points,
the 10 ns/100 us grid, the output norm, and the frozen geometry. It
is **not** the rank of the whole detector or of the true U/V strip H.

Three distinct quantities must not be conflated:

1. **Uncentered SVD_ORACLE** projects a held-out true RKF waveform into
   a basis trained on other ion-start positions. Its coefficients use
   the true held-out waveform. This is a compression bound, **not**
   a fast prediction or avalanche generator.
2. **Physical-coordinate predictors** learn linear response functions
   of birth coordinates from training sites, then predict held-out
   single-ion RKF waveforms from the birth coordinates alone.
   Feature families: G/monopole, azimuthal dipole, radial/dipole,
   second angular harmonic, and a hypothesized near-separatrix gate.
   Models fit separate plus-v and minus-v populations. These
   linear features can be summed into weighted cloud moments at
   **fixed birth time**; differing birth times must be time-binned
   or convolved explicitly. They are not identical to Gemini's
   proposed nine-number avalanche descriptor.
3. **IDW4-coordinate** is an additional spatial interpolation baseline,
   on the same held-out starts; it is not a direct-RKF full-muon
   reference. This pilot is distinct from the three-muon 4.81% L2 study.

Results include median/p90/worst held-out per-ion whole-plane current
L2, separate weak-channel-floor L2, early-100 ns **absolute** induced
charge errors, and 100 us recorded (not necessarily final) charge error.

The split excludes test site rows from fitting but comes from one original
source muon. Generalization across independent muons, source channels,
wire phases, ion-reservoir realizations, and *especially* validated
physical U/V strips remains **unmeasured**.

## First WSL test (no Garfield needed)

In a terminal in your WSL environment, use a **new** checkout. Do not
switch or pull inside `~/na6p/cathode-overnight-2100` while its
simulation/recovery jobs might still be active.

~~~bash
git clone --branch feature/mwpc-avalanche-response-rank-pilot-20261121 \
  --single-branch https://github.com/StasBren/NA6PRoot.git \
  "$HOME/na6p/response-rank-pilot-20261121"
cd "$HOME/na6p/response-rank-pilot-20261121"

python3 -m venv .venv
source .venv/bin/activate
python -m pip install numpy uproot awkward

SCRIPT=test/mwpc-stage-c/cathode-ion-reference/study_response_rank_and_moments.py
python "$SCRIPT" --self-test

BANK="$HOME/na6p/cathode-timing-2100/test_runs/mwpc_stage_c/plane_timing_dt10_v1/templates256_dt10_training.root"
test -s "$BANK" || { echo "MISSING $BANK"; exit 1; }
sha256sum "$BANK"
git rev-parse HEAD
OUT="$PWD/test_runs/mwpc_stage_c/response_rank_pilot_first"
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python "$SCRIPT" \
  --bank-root "$BANK" --out-dir "$OUT" --seed 210021 --max-rank 32
cat "$OUT/metadata.json"
cat "$OUT/results.csv"
head -n 36 "$OUT/spectrum.csv"
~~~

find "$HOME/na6p" -type f -name 'templates256_dt10_training.root' -print
~~~

This first test requires only the existing ROOT and a modest Python

## Sanity checks before interpreting

- If `--self-test` fails, stop: do not interpret ROOT results.
- If the ROOT file has 100 ns templates, stop: first locate the 10 ns
  recalculation. Do not compare differently binned operator ranks.
- If the source contains only one hemisphere, do not infer opposite
  cathode drift from an assumed reflected training population.
- A low SVD oracle error and high physical predictor error means the
  response is compressible but the tested physical coordinates do not
  *predict* the compressed coefficients.
- A good single-ion result does **not** imply preservation of full-muon
  wire multiplicity, avalanche gain tails, electron prompt current, or
  U/V charge-sharing fidelity.

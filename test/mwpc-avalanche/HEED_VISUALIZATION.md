# Heed + Garfield muon visualisation

This branch adds a small presentation-oriented visualisation of the Phase-A
microscopic chain.

It is intentionally separate from the full detector simulation.

## What the visualisation shows

1. one 10 GeV/c muon crossing the idealised MWPC gas cell;
2. Heed ionisation clusters and the low-energy conduction-electron seeds
   generated by the ionisation cascade;
3. microscopic Garfield/Magboltz drift lines of a subset of those electrons.

The GIF is based on the simulated event data, not on a hand-drawn trajectory.

The first version does **not** include avalanche multiplication. That should be
added as a separate visualisation step after the Heed -> drift animation is
validated.

## Coordinate convention

The Phase-A sandbox uses

- Garfield x = local u = across anode wires;
- Garfield y = local v = chamber normal;
- Garfield z = local w = along anode wires.

The GIF shows the u-v projection. The CSV also contains w, so another projection
or 3-D rendering can be added later.

## Build

From the repository root:

```bash
source ~/na6p/env.sh
source ~/na6p/install/garfieldpp/share/Garfield/setupGarfield.sh

cd ~/na6p/src/NA6PRoot-mwpc/test/mwpc-avalanche

cmake -S . -B build \
  -DGarfield_DIR="$HOME/na6p/install/garfieldpp/lib/cmake/Garfield"

cmake --build build -j4
```

## Generate one microscopic event

```bash
./build/mwpc_heed_visualization \
  --pitch-mm 4 \
  --gap-minus-mm 2 \
  --gap-plus-mm 4 \
  --wire-diam-um 30 \
  --hv 1800 \
  --b 0 \
  --u0-mm 1.0 \
  --momentum-gev 10 \
  --sample-mode balanced \
  --max-electrons 40 \
  --max-per-cluster 3 \
  --rng-seed 12345 \
  --max-path-points 250 \
  --output-prefix heed_vis
```

This writes

```text
heed_vis_meta.txt
heed_vis_clusters.csv
heed_vis_electrons.csv
heed_vis_paths.csv
```

The path file contains actual Garfield microscopic drift-line points.

By default, the displayed electrons are selected in `balanced` mode after the
complete Heed event has been generated. The selector samples electrons across
many clusters instead of taking only the first electrons from the first large
cluster. The full Heed cluster/electron event is still written to CSV; only the
subset sent to Garfield for the presentation trajectories is reduced.

## Install the Python plotting dependencies

Only needed if they are not already available:

```bash
python3 -m pip install --user matplotlib pillow
```

If the system Python refuses user-site installation, create a small virtual
environment instead:

```bash
python3 -m venv .venv-vis
source .venv-vis/bin/activate
python -m pip install matplotlib pillow
```

## Make the GIF

```bash
python3 render_heed_gif.py \
  --prefix heed_vis \
  --output heed_muon_drift.gif
```

The default animation is about 7 seconds long and has three stages:

- muon crossing;
- Heed clusters appearing;
- Garfield electron drift.

To keep the intermediate PNG frames:

```bash
python3 render_heed_gif.py \
  --prefix heed_vis \
  --output heed_muon_drift.gif \
  --keep-frames
```

## Useful variations

More electrons:

```bash
./build/mwpc_heed_visualization --max-electrons 80
```

Start at the wire-cell boundary:

```bash
./build/mwpc_heed_visualization --u0-mm 2.0
```

Magnetic-field sensitivity example:

```bash
./build/mwpc_heed_visualization --b 1.0
```

Note that the first GIF is a u-v projection. The main Lorentz displacement for
the nominal NA60 field is along local w, so a B-field presentation animation
should later use the w-v projection or a 3-D view.

## Interpretation

Heed and Garfield have distinct roles here:

```text
muon track
  -> Heed ionisation clusters
  -> Heed low-energy conduction-electron seed positions
  -> Garfield/Magboltz microscopic electron transport
  -> anode-wire collection / attachment
```

With Heed delta-electron transport enabled, the position and time returned for
each low-energy conduction electron are used as the handoff to Garfield. The
Heed energy/direction of these final low-energy electrons are not treated as a
meaningful initial momentum; the drift is started at 0.1 eV with zero direction,
so AvalancheMicroscopic randomises the initial direction and then follows the
individual gas collisions.

## Current limitations

- one idealised MWPC cell;
- one muon event at a time;
- no avalanche multiplication in this GIF;
- no cathode-strip signal;
- no VMM response;
- no real Geant4 -> TGeo global-to-local handoff yet.

Those are deliberate boundaries: this animation is meant to illustrate the
validated Phase-A Heed -> drift handoff cleanly.


## Presentation comparison: near-wire vs midpoint

The renderer now shows only the two anode wires bracketing the displayed muon.
This affects only the figure; the Garfield field component still contains the
same nine-wire local array.

The quickest way to generate the two recommended presentation GIFs is:

```bash
bash make_heed_demo_gifs.sh
```

This produces:

```text
heed_nearwire.gif
heed_midpoint.gif
```

The near-wire example uses `u0 = 0.4 mm`. The midpoint example uses
`u0 = 2.0 mm` for the 4 mm pitch reference cell, i.e. halfway between the
wires at 0 and 4 mm.

These are two independent stochastic Heed events. They are intended as
illustrative animations, not as a controlled quantitative comparison of two
identical ionisation histories.
